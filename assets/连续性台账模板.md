# 连续性台账 · 〔项目名〕

> 一个项目一份，放在项目根目录。**每集写前读账、写后更新。**
> 正文与台账冲突时先停下问清哪边改，不要凭记忆复述前情。
> 方法与取舍见 `references/19-consistency-playbook.md` 第三·补节。

## ① 伏笔账

| ID | 伏笔内容 | 埋于 | 拟收于 | 状态 | 收法 / 备注 |
|---|---|---:|---:|---|---|
| FB-01 | 〔一句话说清这个伏笔是什么物件/信息/动作〕 | 3 | 28 | 养 | 〔收的时候怎么解释〕 |
| FB-02 |  |  |  | 埋 |  |

**状态取值**：`埋`（已出现未见效）/ `养`（已出现并推进过）/ `收`（已解释）/ `弃`（明确放弃，备注写原因）

**密度参考**：每 10 集至少 2 埋 1 收。只埋不收观众无感，秒埋秒收无回味。

## ② 人物账

| 角色 | 首次出场 | 当前状态 | 与主角关系现值 | 最后变动集 | 变动事件 |
|---|---:|---|---|---:|---|
| 〔角色名〕 | 1 | 活着 | 敌对 | 12 | 〔第 12 集他做了什么导致关系变化〕 |

**当前状态取值**：`活着` / `受伤` / `失踪` / `死亡` / `回忆出现`

- **标记为「死亡」的角色，从该集之后不得再出现在听觉轨（台词/旁白）里**，回忆闪回例外——但要在备注写"闪回"。
- 新角色入册必须同步在 `视觉设定.md` 建档，**未建档不得给台词**。

## ③ 道具状态账

| 道具 | 首次出现集 | 持有者 | 当前状态 | 变动集 |
|---|---:|---|---|---:|
| 〔道具名〕 | 3 | 〔谁〕 | 〔在哪、什么状态〕 | 17 |

- 关键道具（参与卡点 / 付费墙 / 反转的）每次易手、损毁、出示都记一行。
- **首次出现集之后才能在正文里被引用**——早于此集出现，是设定泄漏。
- 这一条与视觉锁是两件事：`LOCK-BRASS-KEY-ENGRAVE` 保证「磨痕每镜都在」，道具账保证「这把钥匙第 17 集才出现，第 14 集不该有人拿着它」。

## ④ 世界观规则账

| 规则 | 类别 | 确立集 | 引用集 | 是否被违反 |
|---|---|---:|---|---|
| 〔例：重生只能回到死前 24 小时〕 | 能力边界 | 2 | 5、9、17 | 否 |
| 〔例：每次使用折寿一年〕 | 代价 | 2 | 5、9 | 否 |
| 〔例：不能改变他人已发生的死亡〕 | 禁忌 | 4 | 17 | **是 ← 待修** |

**类别取值**：`能力边界` / `代价` / `禁忌`

- 重生 / 系统 / 规则怪谈类必立，三行齐了才动笔。
- 角色每次使用设定能力，登记一次引用集号。
- **违反 → 直接 FAIL**，不是"下集补一句解释"能救的。

## 读写循环

```
for N in 集数区间:
  1. 读四类账（全读，不要只读相关的）
  2. 读第 N 集规划，定位本集处在哪个单元、哪一拍
  3. 写正文
  4. 跑机检：python scripts/cd.py check .    （L 组查台账）
  5. 更新台账：新伏笔 / 人物变动 / 道具易手 / 规则引用，逐条落账
  6. 每写完 5 集，全账复核一次
```

**第 5 步没做，这一集视为未完成。** 台账更新不是可选项。

## 四类账最容易漏哪一类

按实际项目的漏账率排：

1. **道具状态账**（最常漏）——道具易手往往写在动作里不写在台词里，容易漏记；
2. **世界观规则账**——能力边界写一次就忘，第 20 集突然破例；
3. **伏笔账**——埋的时候记得，收的时候忘了；
4. **人物账**——死人开口最刺眼，反而不容易漏。

## 机检对应

```bash
python scripts/cd.py ledger . --init     # 从视觉设定生成台账骨架（已有则不覆盖）
python scripts/cd.py ledger . --check    # 只查台账本身
python scripts/cd.py check .             # 顺带跑 L 组
```

| 码 | 查什么 |
|---|---|
| **L1** | 多集项目有台账（单集项目 INFO，不强制） |
| **L2** | 伏笔没有超期未收（超过「拟收于 +3 集」） |
| **L3** | 已死亡角色在后续集的听觉轨里没有台词 |
| **L4** | 道具没有早于「首次出现集」被提及 |
