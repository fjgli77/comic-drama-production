## 这是什么

一套给 AI 助手执行的漫剧生产规则库。不是提示词模板合集，是把整条管线的**判断依据**和**失败经验**写成可执行的东西。

核心主张五条：

1. **Markdown 是唯一创作真相**——不建并行的 JSON/索引/覆盖表。创作者要能读、能改、能贴给别人看。
2. **规则分四级**——结构不变量、受审不变量、默认工艺、风格选项。一刀切会把流程做成卡壳机。
3. **一致性靠锚点逐字复用 + 连续性锁**，不靠运气。
4. **提示词按「模型能执行什么」写**——特效不写「粒子」写材质，打戏不写频率写招式序列。
5. **资产是造出来的，不是画出来的**——四格板、九宫格、状态轨迹，每一样都有工程纪律。

## 快速开始

```bash
# 1. 建项目（建完跑 check 会有 FAIL，空项目当然不完整）
python scripts/cd.py init ./my-drama --title "我的漫剧" --episodes 12 \
    --duration 120 --form "国漫二次元" --model seedance-2.5 --platform 红果

# 2. 填 short-drama.json（P0 四道锁 + 合规）
# 3. 写 视觉设定.md（人物/地点/道具条目，每条带资产编号）
# 4. 写 剧集/EP001/剧本.md
python scripts/cd.py estimate ./my-drama/剧集/EP001/剧本.md --target 120

# 5. 从剧本提取角色 → 建卡清单 + 四格板提示词
#    前提：视觉设定已写。它只认「已登记的人名」和「有台词的说话人」
python scripts/cd.py cast ./my-drama

# 6. 出资产（按建卡清单，复制模板改）
#    assets/人物四格板模板.md、场景九宫格模板.md

# 7. 写 剧集/EP001/分镜.md
python scripts/cd.py check ./my-drama

# 8. 资产清单（M1 形态下即《素材接线单》）
python scripts/cd.py assets ./my-drama

# 9. 生成投喂稿骨架
python scripts/cd.py pack ./my-drama --episode EP001 --model seedance-2.5

# 10. 看板
python scripts/cd.py board ./my-drama --with-check

# 反推（拿外部图/片，反推它怎么写出来的，不占流程）
python scripts/cd.py reverse ./refs/frame.png
python scripts/cd.py reverse ./refs/clip.mp4
```

零依赖，纯 Python 标准库，不需要 API Key。

**改过 `cd.py` 之后跑一次自测**，确认检查器本身没坏：

```bash
python scripts/cd.py figure ./my-drama --list              # 11 种人物图式
python scripts/cd.py figure ./my-drama --char 苏衔 -l 三视图 # 按需出提示词
python scripts/cd.py srt ./my-drama --episode EP001        # 出字幕骨架
python scripts/cd.py bench ./my-drama --sec 96 --shots 24 --chars 268  # 与对标同口径比
python scripts/cd.py selftest      # 41/41 项检查有效
```

## 支持哪些模型

**不是列全型号，是让任何型号都能落进五类之一。** 市场几十个模型，提示词写法人只有五种：

| 范式 | 名字 | 代表模型 | 数量 |
|---|---|---|---|
| **A** | 结构化分段（分段+时间轴+分字段） | Seedance 2.5/2.0、MiniMax H3、可灵 3.0、万相 3.0、Vidu Q2、即梦 | 7 |
| **B** | 自然语言散文（一段连续描述） | Veo 3.1、Sora 2、Runway Gen-4、Luma、Pika、PixVerse、LTX、混元、Seedream 4、Qwen-Image、Firefly、Grok、Kolors | 13 |
| **C** | 标签堆叠（关键词+权重） | Midjourney V8、Flux 1.1、SD 3.5、Ideogram 3、Recraft | 5 |
| **D** | 指令式编辑（保持什么+只改什么） | GPT Image 2、Nano Banana Pro、Flux Kontext | 3 |
| **E** | 对话式迭代（逐轮追加） | Gemini Omni | 1 |

```bash
python scripts/cd.py model              # 列出 29 个型号，标范式与上限
python scripts/cd.py model minimax-h3   # 看单个：范式、上限、参考图、音频、写法要点
```

**遇到没登记的模型**，先问一句"它是分段式、散文式、标签式、指令式还是对话式"——
答案出来写法就定了。要登记进机检，改 `scripts/cd.py` 的 `MODEL_PROFILE` 加一条即可。

**换模型只改表达，不改内容**：叙事层/镜头层/光影层一个字不动，只改模型层（秒数、分辨率、
参考槽位、负面词表）。详见 `references/29-model-adapters.md`。

## 九件最容易做错的事

### 一、把「每集一份视觉设定」当正常

第 3 集女主穿青衫，第 17 集变粉的——根因不是记性差，是**每集复制了一份视觉设定**。

正确结构：`视觉设定.md` 全季一份，造型变化用「适用区间」表达。

### 二、资产当「画得像」，而不是「拆得开」

四类资产各有硬纪律，违反任何一条都会在第十集集体爆雷：

- **人物**：禁砍头（头身比失真）、禁「主图+四格」（出 5 格）、禁图上乱码；只写「外卖员」会被画成协警
- **服装**：是**拆解**不是设计，参考图没有的部件必须写「无此结构」，否则模型会给你加披风
- **表情动作**：十二格/十五格，**强度必须拉开**——不写梯度，三个笑会画成同一个
- **武器**：必须给三重长度参照（绝对/人体/攻击半径），否则这一镜匕首、下一镜长剑

### 三、人物四格板当成「画一张立绘」

四格纯图板：1 格面部特写（全图唯一清晰的脸）+ 3 格无脸全身（正面/侧面/背面）。

三条纪律都是踩坑踩出来的：

- **不许砍头**——三格全身必须头部完整入画，只去五官。头不入画，模型失去头身比参照，会忽大忽小；
- **不许写「主图+四格」**——模型按加法出成 5 格，正面画两次；
- **图上除图底短标签外零文字**——中文必乱码，还会被当水印。

还有一条：只写「外卖员」，模型给你画成协警。必须有职业标识物三件套 + 反漂移清单。

### 四、场景当「一张背景图」

**地点与视图要分开**：停电前后是两个视图，仍是一个地点。分错了，跨镜空间会错位。

**九宫格不是九个机位各出一张图**，是 1 张图 = 9 视角 = 1 个素材槽——用来对抗参考图数量上限。

### 五、特效写成「发光的东西」，服装特效写成「衣袂飘飘」

**不要写「粒子」这两个字。**

模型对「粒子」没有物理经验，对「燃烧的铁屑」「火星」「符纸碎屑」有。写「顶级震撼的粒子特效」，出来是一团均匀慢速的半透明彩雾。

两条同源的错：**静图照抄视频写法**（静图没有时间，只能靠中间态 + 景深分层）、**服装特效写成「衣袂飘飘」**（四个字，而布料受力有十几种可画的物理结果）。详见 `11` 第八、九节。

去水五律：禁评价词 / 禁裸光效 / 禁写粒子 / 必写速度差 / 三段论（压缩→爆发→余波）。

### 六、打戏写成「动作很激烈」

写「以极高频率互相攻击」，模型不知道多快。要写成**招式序列 + 落点 + 防守反应**。

还要有**近景对招**——没有近景的打戏，只有爆炸没有枪战。

### 七、把抽象词当提示词

写「压迫感」，模型给皱眉加阴影；写「端坐主位如钟」，殿顶挂下一口钟；写「玉佩不发光」，玉佩发光。

模型按词找画面，不读意图。详见 `references/18-failure-atlas.md`。

### 八、把包装当最后一步

**封面决定点击，点击决定一切。** 一集画面精美但封面平淡的漫剧，播放量可能是同质量的十分之一。

最省力的做法：从成片里挑一帧最好的裁成封面，加 4–6 字，不要另做一张。

封面三要素：一张清晰的脸（占 1/4 以上）、一个可见的冲突、一个信息缺口。

### 九、小说改编当「缩写」

小说用文字制造体验，漫剧用画面和声音制造体验。**中间隔的不是压缩，是换一套因果。**

「她看着冷掉的饭菜，终于死心」不能改成「她攥了攥拳头」——那是假忙活。要改成改变处境的行动：撕掉圈着纪念日的台历，或收起碗筷、把备用钥匙留在玄关。

## 机检能查什么

七组，具体项数随集数与资产数增长（跑一次就知道，输出末尾有「共 N 项」）。

| 组 | 查什么 | 例子 |
|---|---|---|
| **S 结构** | 文件存在、分镜非空、ID 唯一、必需字段、时长区间与加总 | 单镜 12 秒 → FAIL |
| **R 引用** | 视觉依据指向真实条目、锁面逐字出现、槽位格式、**图号唯一** | 引用不存在的人物 / 图号重复 → FAIL |
| **M 模型** | 模型在服役、单段上限一致、参考图不超限、单镜不超上限 | 用停服模型 / 参考超限 → FAIL |
| **Q 条件** | 竖屏空镜、群像事务、旧口径残留（带条件门与豁免） | 9:16 用空镜过渡 / 背景人形立牌 → WARN |
| **X 执行** | 台词字数、台词镜余量、词根污染、一镜一动作、氛围层、**特效去水（视频稿 + 图片稿）** | 33 字台词 / 写「粒子」→ FAIL/WARN |
| **L 台账** | 伏笔超期、已故角色台词、道具早引 | 第 2 集里死人在说话 → FAIL |
| **C 合规** | AI 标识、备案档位、红线自检、画幅与模型锁定 | 未勾选标识 → FAIL |
| **A 资产** | **四格/九格声明、砍头词、马赛克词、全身完整性、职业三件套、自包含** | 写 headless / 打马赛克 → FAIL |

**它不查**：这场戏好不好看、这个选题会不会爆、这张图美不美。那是审查和人的判断。

## 第一次实战：先做一集

不要一上来做 12 集。**先做 1 集，跑完整条链路**，把资产、提示词、机检都过一遍，再决定要不要连载。理由很实际：第 1 集会暴露你八成的方法问题，而那时改成本最低。

最小可行路径：

```
init → 写视觉设定 → 写剧本 → estimate 核时长 → cast 出建卡清单
     → 出 1 份人物板 → 写分镜 → check → pack → 看板
```

一集跑通之后，第 2 集起只需要：写剧本 → 写分镜 → check。视觉设定和资产是复用的。

### 会遇到的三件事

**一、第一次 `check` 一定全是 FAIL。** 这是对的。空项目当然不完整，`init` 生成的是骨架。FAIL 要一条条补到清零，WARN 逐条判断留或改。

**二、`cast` 的顺序不能反。** 它只认「视觉设定里已登记的人名」和「听觉轨里有台词的说话人」。**先写视觉设定，再跑 cast**。反过来跑，清单里只有说话人，画面里出现的人全漏。

**三、`estimate` 折出来的时长通常比你以为的短。** 中文对白按 4.0~4.2 字/秒折算，这已是有实测支撑的偏快值。写 120 秒目标却只折出 70 秒，说明内容量不够，不是折算错了——回去加戏，不要把目标时长改小；也**不要靠加快语速硬塞**，配音会赶词、字幕会截断。

## 边界

**本 Skill 不持有图。** 交付的是提示词与结构数据，图片和视频由你在外部平台生成并持有。

所以有「素材形态」三档：M0 纯提示词 / M1 编号占位（默认）/ M2 已入库。默认 M1——写图号 + 附接线单，你拿提示词去平台自己挂图，不需要把图交回项目。

**本 Skill 也不做创作判断。** 它能保证工艺不出错，不能保证选题会爆。2026 上半年 AI 短剧破亿率 0.47%，AI 漫剧爆款率不足 0.1%——这个赛道最值钱的能力是判断力，不是产能。
