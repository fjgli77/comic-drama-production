# 模型适配矩阵：让一套提示词活过 90% 的市面模型

> 核验日期 2026-11-15。规格来自厂商文档与第三方横评，**厂商自己常常三处说法不一**（Veo 3.1 的 Google 三个页面给三个答案），所以下表的数字都标了把握程度。
>
> 这一篇解决一件事：**你写的提示词不能只对一个模型有效。**

---

## 零·补、先认范式，再认型号

这一篇讲的是**具体型号的差异**。但型号半年换一代，范式不会。
所以顺序是：先判断它属于哪种范式（A~E），再用这一篇查参数。

| 范式 | 名字 | 代表 |
|---|---|---|
| A | 结构化分段 | Seedance / H3 / 可灵 / 万相 / Vidu |
| B | 自然语言散文 | Veo / Runway / Luma / Pika / 混元 / Seedream |
| C | 标签堆叠 | MJ / Flux / SD / Ideogram |
| D | 指令式编辑 | GPT Image 2 / Nano Banana Pro / Flux Kontext |
| E | 对话式迭代 | Gemini Omni |

**本 skill 登记了 29 个型号**，`python scripts/cd.py model` 可查。
范式怎么互转、同一镜头的五种写法对照，见 `29-model-adapters.md`。

## 零、先接受三个事实

### 1. 提示词不是通用语

同一句「镜头缓慢推近她，「在 Seedance 上得到推镜，在 Veo 上可能得到静止，在 Midjourney 上得到一张构图不同的图。

原因是各家把自然语言映射到参数的词典不同：
- Seedance 认 `@material[name]` 这种显式引用语法；
- Veo 认「24fps、8 秒、首尾帧」这类工程参数；
- Kling 认「动作迁移」「大幅度运动」这类行为词；
- Midjourney 完全不吃 JSON，只吃短促的风格串。

**所以「模型方言」必须单独成层，不能混在分镜里。**

### 2. 模型生命周期比项目周期短

Sora 2 已于 2026-09-24 停服，OpenAI 关掉了应用与 API。一年前还是首选的模型，今天已经不能交付。

一个 60 集的漫剧做四个月，这期间大概率会有一个模型换代。

**结论：提示词要写成「可迁移」的，不能写成「只有某模型能读」的。**

### 3. 贵模型不该用来试错

先用最便宜的档位确认「运动对不对」，锁死提示词，再花钱上分辨率。这条习惯比选对模型更省钱。

### 选型：按你的瓶颈选，不按排行榜

| 你的瓶颈 | 选 | 为什么 |

| 一镜要长，不想拼段 | Seedance 2.5 / Wan 3.0 | 30s 单段，Seedance 还能延两次 |

### 路由：按资产类型分派

这是本篇最实用的一张表。**不同资产该用不同模型，不该一个模型打天下。**

| 资产 | 首选 | 理由 | 备选 |
|---|---|---|---|
| 人物四格板 | **Nano Banana Pro** | 四格要「同一个人」，一致性是唯一指标 | Seedream 4.0 |
| 服装设定板 | **Nano Banana Pro** | 三视图 + 部件放大，跨图必须同一件衣服 | GPT Image 2（排版更准） |
| 场景九宫格 | **Nano Banana Pro** | 九格同一空间，最考验一致性 | Seedream 4.0 |
| 道具 / 武器板 | **GPT Image 2** | 六格标题标签要中文字准 | Nano Banana Pro |
| 表情 / 动作板 | Nano Banana Pro | 十二格同一张脸 | Seedream 4.0 |
| **封面** | **GPT Image 2** | 封面必带 4–6 字，字错整张废 | Ideogram |
| 氛围参考图 | Midjourney | 只要气质，不要精确 | Flux |
| 需商用的品牌物料 | Firefly | 训练数据授权干净 | — |

**一句话**：**要一致性找 Nano Banana Pro，要字准找 GPT Image 2，要氛围找 Midjourney。**

### 按图式选模型（人物图专用）

图式（`26-figure-layouts.md`）是**硬约束**，模型是**软约束**。
给一个不支持多主体的模型写"全图共 4 格"，它照样给你一张单人图，或者一张诡异的拼贴。

| 图式 | 首选 | 理由 | 别用 |
|---|---|---|---|
| `three-view` / `four-view` | **Nano Banana Pro** | 一次多视图且同一人，目前最稳 | Midjourney（出拼贴）、纯文生图 SD（不认格） |
| `expression` | **Nano Banana Pro** | 4/6/9 格同一张脸 | MJ（每格脸不同） |
| `pose` | Seedream 4.0 / Nano Banana | 动作幅度大，国风动作语义强 | MJ（动作易僵） |
| `profile` 档案海报 | **GPT Image 2** | 分区排版 + 中文字准，一格都不能错位 | MJ（文字必崩）、Flux（排版弱） |
| `fullbody` / `portrait` | Seedream 4.0 / MJ / Flux | 单主体，按风格气质选 | — |
| `kv` | Seedream 4.0 / MJ | 氛围与光 | GPT Image 2（偏平面、少空气感） |
| `lineup` | **Nano Banana Pro** | 多人同框还得不同脸，最难的一项 | MJ（全部同脸） |
| `chibi` | Seedream 4.0 | 国风 Q 版审美 | — |

**多格图的三个实操前提**（缺一个就会崩）：

1. **模型要支持一次出多主体**——否则拆成单张分别出，再用一致性手段（参考图 / 角色 LoRA）拉齐
2. **画幅要够宽**——16:9 放 3~4 格；9:16 硬塞四格，每格只剩 1/4 宽，脸必糊
3. **格数要写死并封顶**——"仅此 N 格，不出现第 N+1 格"，否则模型按加法给你加一格

## 三、方言差异：同一镜头，三种写法

这是从「会用模型」到「会用一组模型」的分界线。同一镜，写三遍：

### 目标镜
> 沈惊歌抬眼看向画外右侧，嘴角向一侧抬起。中近景，固定机位，台灯暖光从右后方切入。

### Seedance 2.5 写法
```
@image1 中的女性（沈惊歌）抬眼看画外向右侧，嘴角单侧抬起。
中近景，机位固定不动。台灯暖黄硬光自画面右后方切入，右脸被切亮，左侧留深影。
参考 @image1 保持面部与发型完全一致；本镜只允许头部与眼神变化，身体不动。
4 秒，9:16，24fps。
```
要点：**显式引用 @image1**；把「不动」写成禁止项；给秒数。

### Veo 3.1 写法
```
Static medium close-up. Woman looks up toward frame right, one corner of her mouth
lifting. Warm tungsten key light from back-right rakes across her right cheek,
leaving the left side in deep shadow. No camera movement. 24fps.
```
要点：**英文、工程参数、句子短**；8 秒上限，别指望一镜讲完一段戏；首尾帧能控就控。

### Kling 3.0 写法
```
动作：抬头 + 眼神右移 + 嘴角单侧上扬，幅度小，0.6 秒完成，之后保持静止。
镜头：固定，无推拉摇移。
风格：写实，暖调，浅景深。
```
要点：**把动作拆成可执行的行为项**并给时长；Kling 对「幅度」「速度」敏感，对文学描写不敏感。

### 三者的共同骨架
不管哪个模型，都包含这四样：**主体是谁（靠参考/引用）、做什么（一个动作）、镜头怎么放（位置+运动）、光怎么打（方向+色温）**。

**方言只改「怎么说」，不改「说什么」。** 所以分镜层写「说什么」，模型层才写「怎么说」——这就是为什么 `13-storyboard.md` 不许出现模型参数。

## 四、提示词的模型无关层与模型相关层

写提示词时，逐句问自己：这句是哪个层的？

| 层 | 内容 | 换模型要改吗 |
|---|---|---|
| **叙事层** | 谁、在哪、做什么、情绪是什么 | ❌ 不改 |
| **镜头层** | 景别、角度、机位运动、轴线 | ❌ 不改（但方言词不同） |
| **光影层** | 光源方向、色温、光比、气氛 | ❌ 不改 |
| **模型层** | 秒数、分辨率、帧率、引用语法、参考槽位、负面词表 | ✅ **必须改** |

**实操建议**：把前两层写进 `分镜.md`（模型无关），第四层写进 `视频提示词.md` 的段首声明（模型相关）。换模型时只重写后者。

## 五、降级与迁移

### 目标模型不可用时（停服 / 限额 / 涨价）

按这个顺序处理，不要重写分镜：

1. **查规格差**：新模型的单段上限、参考位数量、原生音频有无
2. **拆段或并段**：上限变小 → 按 `13-storyboard.md` 的段缝规则拆；上限变大 → 并段（注意并段会丢镜间呼吸）
3. **重排参考槽位**：参考位从 50 降到 12，就要决定先保留哪几张
   - 有九宫格故事板时，**故事板可放第一槽**（有实测支持，见 `19-consistency-playbook.md`）
   - 无故事板时，**角色优先**（人脸崩了无法补救）
   - 顺序不要凭直觉定，在你的目标模型上跑一次两槽互换的 A/B，两个 4 秒 480p 片段就够
4. **重写方言层**：按第三节的三种写法改
5. **重跑 G 组机检**：段时长、参考数、方言词

### 模型升级时

新模型通常变长、变清晰，但会带来新坑：

| 升级方向 | 新坑 | 对策 |
|---|---|---|
| 单段变长（15s → 30s） | 模型在中段自己加戏 | 提示词里写「全段只有这一个动作，其余保持静止」 |
| 参考位变多（9 → 50） | 参考互相打架，脸的来源不明 | 每个参考标用途：`@image1 只控制脸，不控制服装` |
| 支持原生音频 | 自动生成的音乐盖住你要的静默 | 明确写「无背景音乐，仅环境音」 |
| 支持多镜头（2.5 的多镜头模式） | 段缝由模型决定，你失去剪辑权 | 重要节奏点仍然手动分段 |

## 六、成本纪律

| 阶段 | 用什么 | 为什么 |
|---|---|---|
| 试运动 | 最便宜档（Seedance 2.0 Mini / Wan 480p） | 你只看运动对不对，不看清不清晰 |
| 锁提示词 | 同上 | 提示词定了再花钱 |
| 出正片 | 目标模型的目标分辨率 | 此时才值得 |
| 返修单镜 | 目标模型，但可降一档分辨率先验 | 返修常常要试 3–5 次 |

**一条硬规矩**：不要在没锁定提示词的情况下，用最贵的模型跑第一条。

## 七、写进项目的字段

`short-drama.json` 的 `spec` 段至少要这三个：

```json
{
  "spec": {
    "target_model": "seedance-2.5",
    "aspect_ratio": "9:16",
    "duration_cap_sec": 30
  }
}
```

`duration_cap_sec` 是**单段上限**，机检用它拦「一镜写 40 秒」。换模型时必须同步改这个值——它是 `M` 组检查的依据。

可选：
```json
{
  "image_model": "nano-banana-pro",
  "fallback_model": "seedance-2.0",
  "draft_model": "seedance-2.0-mini"
}
```
