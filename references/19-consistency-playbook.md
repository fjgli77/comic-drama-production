# 一致性手册

一致性不是「画得像」，是**观众相信这是同一个人、同一个地方、同一件东西**。

它分三层，每层的解法完全不同。搞混层，就会用错方法。

---

## 一、四层一致性

| 层 | 保什么 | 失效后果 | 主要手段 |
|---|---|---|---|
| **身份层** | 这张脸是谁 | 换脸、脸盲 | 锚点 + 身份参考图 |
| **造型层** | 这一集穿什么、伤在哪 | 服装跳变、伤口位置漂移 | 造型条目 + 连续性锁 |
| **空间层** | 东西在哪、门窗什么状态 | 方位混乱、道具消失 | 场景锚点 + 站位声明 |
| **叙事层** | 这人死没死、东西在谁手里、伏笔埋了几集 | 死人开口、道具凭空出现、伏笔烂尾 | **四类台账**（见第四节） |

**四层的失效原因不同，所以不能用一个方法解决。**

- 身份层坏了 → 加参考图；
- 造型层坏了 → 加锁；
- 空间层坏了 → 加站位；
- 叙事层坏了 → 加台账。

前三层管「看起来对不对」，第四层管「讲得通不通」。**画得很像但人在第 12 集已经死了，前三个层都救不了。**

用「多写几遍描述」去救空间层，是无效劳动。

## 二、跨镜一致性

### 身份层：锚点逐字复用

同一角色的识别锚点，在每个镜头、每条提示词里**逐字复制**，包括标点。

```
第 3 镜：24岁东亚女性，鹅蛋脸，眼尾上挑，左眉尾有一道浅疤，锁骨下方一颗小痣，身形偏瘦。
第 27 镜：24岁东亚女性，鹅蛋脸，眼尾上挑，左眉尾有一道浅疤，锁骨下方一颗小痣，身形偏瘦。
```

**禁止同义改写。**「浅疤」不能变「淡疤」，「鹅蛋脸」不能变「椭圆脸」。改一个字，模型就重新推断一次。

### 造型层：锁 + 状态变化

| 该锁 | 该写状态变化 |
|---|---|
| 服装主色与形制 | 袖口湿了 |
| 发型长度与颜色 | 头发散了 |
| 伤口位置 | 血渗出来了 |
| 道具颜色材质 | 道具表面沾了灰 |

**分界线**：这一集里不会变 → 锁；会变 → 状态变化（写清「哪场之后」）。

### 空间层：场景锚点 + 站位声明

场景锚点写一次（方位 + 固定陈设），站位声明每场写一次（谁在哪、朝哪、依托什么）。

**镜行只写位移增量与依托物**，不重复绝对左右。理由见 `15-video-prompts.md` 的「单一方位权威」。

## 三、跨集一致性

跨集只有三样东西必须延续：

| 延续什么 | 存在哪 |
|---|---|
| **识别锚点** | 视觉设定（人物条目，全季共用一份） |
| **连续性锁** | 视觉设定（锁面跨集不变） |
| **造型演进** | 造型条目（按集标注适用区间） |

### 视觉设定应该是全季一份

**不要每集复制一份视觉设定。** 那必然导致第 17 集的锚点和第 3 集不一样。

正确结构：

```
my-drama/
├── 视觉设定.md            ← 全季共用，人物/地点/道具在这里
└── 剧集/
    ├── EP001/
    │   ├── 剧本.md
    │   ├── 分镜.md
    │   ├── 图片提示词.md
    │   └── 视频提示词.md
    └── EP002/
        └── ...
```

造型条目如果跨集变化，在条目里写清区间：

```markdown
## 造型 · 沈惊歌-破产日
- 适用：EP001-SC001 至 EP004-SC002

## 造型 · 沈惊歌-复起
- 适用：EP004-SC003 起
- 变化原因：EP004-SC002 拿到黑卡后更换
```

### 跨集最常崩的三处

| 崩点 | 原因 | 防法 |
|---|---|---|
| 第 17 集女主衣服变粉 | 造型条目没写适用区间 | 每个造型标起止集 |
| 第 22 集大殿换屋顶 | 场景条目被局部改了 | 场景锚点只增不改 |
| 新出场角色画风跳 | 没走视觉设定，直接写提示词 | 新角色必须先进视觉设定 |

## 三·补、叙事台账：四类账

视觉一致性靠锁，**叙事一致性靠账**。两者管的事不重叠：锁管「这一镜画面里有没有那枚戒指」，账管「那枚戒指现在在谁手里」。

### 铁律：无台账不开写

多集连写不崩的唯一保障。**每集写前读账、写后更新**。台账是唯一事实源，正文与台账冲突时先停下问清哪边改，不要凭记忆复述前情。

四类账，一个项目一份，放在 `连续性台账.md`：

### ① 伏笔账

| ID | 伏笔内容 | 埋于 | 拟收于 | 状态 | 备注 |
|---|---|---:|---:|---|---|
| FB-01 | 染血旧怀表 | 3 | 28 | 养 | 林家旧账物证 |

- 每集规划时必须登记本集**新埋**的伏笔，ID 连续编号；
- 回收时状态改「收」并记录收法；
- 超过拟定集数 3 集未收 → 报超期；
- 密度参考：**每 10 集至少 2 埋 1 收**。只埋不收观众无感，秒埋秒收无回味。

### ② 人物账（存活与关系状态机）

| 角色 | 首次出场 | 当前状态 | 与主角关系现值 | 最后变动集 |
|---|---:|---|---|---:|

- **死人不能再开口**（回忆闪回的直接对白除外）；
- 状态变化必须写集号与触发事件；
- 新角色入册必须同步建档，**未建档不得给台词**。

### ③ 道具状态账

| 道具 | 持有者 | 当前状态 | 变动集 |
|---|---|---|---:|
| 黄铜钥匙 | 沈惊歌 | 第 17 集从门缝摸出，揣进内袋 | 17 |

- 关键道具（参与卡点 / 付费墙 / 反转的）每次易手、损毁、出示都记一行；
- 断章用到道具特写的，写前必须核对当前持有者。

**这一条与视觉锁是两件事**：`LOCK-BRASS-KEY-ENGRAVE` 保证「柄上的磨痕每镜都在」，道具账保证「这把钥匙第 17 集才出现，第 14 集不该有人拿着它」。

### ④ 世界观规则账

| 规则 | 确立集 | 引用集 | 是否被违反 |
|---|---:|---|---|

- 重生 / 系统 / 规则怪谈类必立：**能力边界、代价、禁忌**各成一行；
- 角色每次使用设定能力，登记一次引用；
- 违反规则 → 直接 FAIL。

### 台账不是文档，是文件

四类账写在项目根的 `连续性台账.md`，**有模板、有命令、有机检**：

```bash
python scripts/cd.py ledger ./my-drama --init    # 从剧本与视觉设定生成骨架
python scripts/cd.py ledger ./my-drama           # 摘要：未收伏笔、死亡角色、道具数
python scripts/cd.py ledger ./my-drama --check   # 只跑 L 组
```

`--init` 会做三件省事的事：把每位角色的**首次出场集**从剧本里数出来填好；
把视觉设定里已登记的道具列进道具账；顺手统计每个角色说了几句（方便核人物账）。
系统音、旁白、电话音这类非人物声源不会被误列进人物账。

机检（L 组）查四条：

| 码 | 查什么 | 说明 |
|---|---|---|
| **L1** | 多集项目有台账 | 单集只报 INFO，不强制 |
| **L2** | 伏笔没超期 | 超过「拟收于 +3 集」仍未收 → 报警 |
| **L3** | 已故角色不再有台词 | **自动做别名归一**：台账写「执法长老」、剧本写「长老」，能对上 |
| **L4** | 道具不早于首次出现集 | 第 3 集才出现的钥匙，第 1 集不该有人提 |

**L3 是最容易翻车的一条。** 死人在第 20 集说了一句话，观众不会出戏，但会"感觉哪里不对"——
因为前面铺垫的情感重量被悄悄抹掉了。这条机器能查，就别靠人记。

### 读写循环

```
for N in 集数区间:
  1. 读四类账（全读）
  2. 读第 N 集规划，定位本集处在哪个单元、哪一拍
  3. 写正文
  4. 跑机检，FAIL 即修
  5. 更新台账：新伏笔 / 人物变动 / 道具易手 / 规则引用，逐条落账
  6. 每写完 5 集，全账复核一次
```

**第 5 步没做，这一集视为未完成。** 台账更新不是可选项。

### 四类账最容易漏哪一类

按实际项目的漏账率排：

1. **道具状态账**（最常漏）——因为道具易手往往写在动作里，不写在台词里，容易漏记；
2. **世界观规则账**——能力边界写一次就忘，第 20 集突然破例；
3. **伏笔账**——埋的时候记得，收的时候忘了；
4. 人物账——死人开口最刺眼，反而不容易漏。

## 四、锁脸方案对比

四种手段，成本与效果差很多。

| 方案 | 原理 | 一致性 | 成本 | 适用 |
|---|---|---|---|---|
| **文字锚点** | 用固定短语描述 | 低（40–60%） | 零 | M0 形态、试水 |
| **参考图** | 传图给模型锁形象 | 中高（80–90%） | 低 | **默认方案** |
| **固定 seed** | 同种子同初始化 | 中（同模型同参数下） | 零 | 辅助，不能单独用 |
| **LoRA / 专属模型** | 训练角色模型 | 高（95%+） | 高（需训练） | 长连载、IP 化 |

### 推荐组合

```
文字锚点（锁语义）+ 身份参考图（锁形象）+ 固定 seed（锁随机性）
```

三者叠加能到 90% 以上。要更高只能上 LoRA。

### 参考图的三个坑

| 坑 | 表现 | 修法 |
|---|---|---|
| 参考图过度继承 | 连构图、姿势一起抄 | 写清「不得控制：构图、动作、表情」 |
| 参考图与锚点冲突 | 图里没疤，锚点写了疤 | 锚点只写图里有的特征 |
| 平光参考图 | 出片塑料感 | 加光向与景深描述覆盖 |

### 多参考图的槽位顺序：有一个与直觉相反的实测

直觉上应该「角色图放第一槽」，因为人脸最重要。

但有一组受控 A/B 测试给出了相反结果（模型 StarVideo 2.0，image2video，480p / 4 秒 / 关声音，三个非真人合成输入，只互换前两槽）：

| 组 | 顺序 | 得分 | 差异 |
|---|---|---:|---|
| A | 角色 → 故事板 → 场景 | 28/30 | — |
| B | **故事板 → 角色 → 场景** | **30/30** | 身份稳定性与首帧洁净度更好 |

**故事板放第一槽反而更稳。**

可能的解释：首帧干净（没有人物糊在画面里）能让模型先建立构图，再往里填人；反过来先塞人物，模型会先定人形再挤构图，两头都松。

**但这条结论的边界要写清**：

- 单一模型、单次 A/B、样本很小，**原作者自己也标注「不外推为其他模式或单图场景的普遍规律」**；
- 只在「多参考图 + 图生视频 + 有九宫格故事板」这个组合下成立；
- 单图参考、纯文生视频、其他模型，仍按「角色优先」。

**正确做法不是照抄顺序，是自己在目标模型上跑一次两槽互换的 A/B。** 成本是两个 4 秒 480p 片段，比后面返修十次便宜。

## 五、返修定位

一镜坏了，先定位是哪一层的错，再决定改什么。**不要一上来就重画。**

```
症状 → 层 → 改什么
```

| 症状 | 层 | 改哪里 |
|---|---|---|
| 脸不像 | 身份 | 加/换身份图；锚点对齐图 |
| 衣服变了 | 造型 | 检查造型条目与锁 |
| 方位乱了 | 空间 | 补站位声明，查轴线 |
| 动作没做出来 | 提示词 | 查是否超动作预算，是否属高风险动作 |
| 平光 | 提示词 | 补氛围六件套 |
| 画面出现奇怪的东西 | 提示词 | 扫比喻与抽象词 |
| 人物分身 | 提示词 | 查同框人数与旁观动词 |
| 卡住生成不出来 | 提示词 | 查物理死锁组合 |
| 姿态回退 | 分镜 | 补维持句 |
| 前后接不上 | 分镜 | 查上一镜终点与下一镜起点 |

### 返修最小化原则

**改一镜，不动其他镜。**

这意味着：
- 镜头 ID 稳定（改内容不改 ID）；
- 提示词按镜独立（不共用一段提示词）；
- 参考图按镜绑定（不靠全局设置）。

做到这三条，单镜返修的成本是分钟级；做不到，任何一处改动都要全片重跑。

## 六、版本管理

### 锚点要改怎么办

**不要局部手改。** 手改必然漏。

正确流程：

1. 在视觉设定里改锚点，标注版本：`锚点 v2（2026-11-15 修改：删除「锁骨痣」，因与参考图不一致）`；
2. 全局搜索该锚点原文，一次性替换所有出现处；
3. 重跑机检，确认没有残留旧锚点；
4. 已生成的图标注「基于 v1」，需要时重出。

### 提示词版本

每条可投喂提示词带一个版本标记（写在文档里，不写进正文）：

```markdown
## MOTION-EP001-003 · 掐进掌心
- 版本：v2（v1 起手姿态错误，已按分镜起点修正）
- 分镜：SHOT-EP001-003
```

**正文里不写版本号**，正文必须纯净可复制。

### 什么时候该重开

| 情况 | 处理 |
|---|---|
| 改一句台词 | 就地改，重算时长 |
| 改一镜 | 就地改，重跑该镜 |
| 改造型 | 新造型条目，旧条目写失效区间 |
| 改画风 | **全片重开**，不要混 |
| 改画幅 | **全片重开**，构图全部失效 |
| 改目标模型 | **全片重写提示词**，语法契约不同 |

后三项是伤筋动骨的，立项时就要定死。

## 七、多版本复用

同一部剧要出多语言版、多平台版时：

| 复用 | 不复用 |
|---|---|
| 画面（关键帧 + 视频） | 字幕 |
| 分镜结构 | 配音 |
| 音量包络 | 台词文本 |
| BGM | — |

**核心原则：换音频字幕，不换画面。**

前提是画面上**没有烧录文字**。所以投喂时就要声明「不生成任何非画内字幕」——一旦画面上有字，多语言版本就只能重做。

这条在立项时就要决定，事后无法补救。

## 八、一致性自检

- [ ] 视觉设定是全季一份，不是每集一份？
- [ ] 每个角色的锚点 30–60 字，且都是可画事实？
- [ ] 造型条目有适用区间？
- [ ] 会变的写进状态变化，不会变的上了锁？
- [ ] 锁面是短名词短语，且逐字出现在正文里？
- [ ] 场景锚点写了方位？
- [ ] 镜行没有重复绝对左右？
- [ ] 身份用了「锚点 + 参考图 + seed」三重？
- [ ] 参考图标了「不得控制什么」？
- [ ] 画面没有烧录文字（为多语言留路）？
- [ ] 改锚点时走了全局替换，不是局部手改？

第 1 题是最常见的架构性错误——每集一份视觉设定，一致性必然在第三集之后崩。
